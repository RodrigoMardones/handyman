## 4. Mecánica del harness (aprendida — para no re-descubrir)

- **Patrón por feature:** worktree + branch desde integración → implementer (agente en
  background) → review adversarial → *yo* mergeo → cierro 1-a-la-vez en el checkout principal.
- **Agentes:** los roles del harness (`implementer`/`reviewer`) tienen frontmatter `tools` con
  nombres que este runtime NO reconoce → se lanzan con 0 tools y fallan. **Usar `general-purpose`.**
  (Deuda pendiente: arreglar esos frontmatters → mapear a `Read/Edit/Bash/Grep/...`.)
- **`.handyman/` gitignored:** el estado del harness (feature_list, progress, backlog, docs) NO
  se commitea. Los worktrees frescos NO lo tienen (por eso `./init.sh` da exit 1 en un worktree
  sin `.handyman`, y exit 0 en el checkout principal). El leader gestiona el estado en el principal.
- **Suite self-building:** cada `tests/test_X.sh` portado hace `(cd handyman && npm run build)` →
  necesita `node_modules` instalado. Tras clonar/mergear en el principal: `(cd handyman && npm install)`.
- **Rutas dist↔scripts:** los `.ts` resuelven hermanos (`../scripts/preflight.py`, `assets/`,
  `schemas/`) vía `import.meta.url` (patrón en `core/schema.ts`, `backlog.ts`) — funciona desde
  `src/` y `dist/`.
- **Paridad:** comparar ARCHIVOS resultantes byte-a-byte, no solo stdout. Normalizar únicamente
  paths absolutos y prog name (`.py`→`.js`). Los errores de argparse comparten todo menos el prog.
- **Riesgos del plan ya de-riesgados en código:** half-even (`core/formatHalfEven`),
  ensure_ascii=True (post-pass de escape en metrics `--json`), exit-2 argparse (shim en
  `backlog.ts`, reusado por `feature.ts`), `_parse_frontmatter` (`core/frontmatter.ts`).
- **Trailers de commit:** los ports llevan `Co-Authored-By: Claude Opus 4.8 (1M context)` y/o
  `Claude Fable 5`. Un `--amend` sobre un commit del propio workflow disparó un WARNING de
  seguridad benigno (rama local sin push, reflog limpio) — es esperado, no un problema.
