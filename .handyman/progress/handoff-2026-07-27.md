## 2. Operational state & gotchas (read before running anything)

- **Nothing runs right now.** To work the agent you need both: `node handyman/dist/mcp.js --http --port 8177` and `cd agents/flue-handyman && set -a && . ../../.env && set +a && HANDYMAN_PROJECT_ROOT=<target> npx flue dev`. Driver: `node run-feature.mjs <feature>`; evals: `pnpm evals`.
- **Scratch project `/tmp/hm-flue-spike` is volatile** (tmpfs): recreate with `bash handyman/scripts/scaffold.sh local /tmp/hm-flue-spike spike-project` + replace its `init.sh` with a trivial `exit 0`. The evals and all spike evidence assumed it.
- Keys in root `.env`: `Z_AI_API_KEY` (works) and `MOONSHOT_API_KEY` which is **actually a Kimi for Coding token** (`api.kimi.com/coding` accepts it, `api.moonshot.ai` 401s). `src/app.ts` feeds it to `kimi-coding` via `KIMI_API_KEY ?? MOONSHOT_API_KEY`; cleanup = rename the var and drop the fallback.
- GLM needs `thinkingLevel: 'minimal'` + `maxTokens: 16384` (burns budget on thinking; default config returned 1 empty token).
- Long loops: use `agents.send` + `agents.wait` (blocking `prompt` dies ~300s with `HeadersTimeoutError`; backend finishes anyway). `wait` resolves flat `{ text, usage, model }`, not `prompt`'s `{ result }` envelope.
- `flue dev` watcher must not see file edits while a run is in flight (`Runtime drain timed out` → state `failed`; restart). For long sessions prefer `flue build` + `node dist/server.mjs`.
- pnpm is strict: every direct import must be a declared dep (`hono` was the casualty).
